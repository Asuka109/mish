# Public-Release Documentation and Compliance Review

This review records the material public-facing findings for the documentation
PR prepared from `origin/main` at `cbe281c` on 2026-07-23. It is an engineering
audit, not legal advice. The completed macOS packaging-readiness audit selected
a System Proxy-only first public release. The reconciled claims below distinguish
that path from a future TUN-enabled distribution.

## Automated controls

`pnpm check:public-release` now verifies:

- required public and packaged legal resources;
- the canonical GPLv3 license-text digest;
- `GPL-3.0-only` consistency across Mish npm and Cargo manifests;
- the pinned Mihomo version, commit, source, license, and non-affiliation notice;
- disclosure of material direct dependencies, artwork, remote icons, and the
  unresolved Highcharts license boundary; and
- conservative README claims for release status, platform support, hosted
  services, the completed packaging audit, and the System Proxy-only/TUN release
  split.

`pnpm check:docs` runs the public-release check after validating local Markdown
links.

## Decisions required before public distribution

1. Implement and verify an explicit signed System Proxy-only distribution mode
   that omits the privileged helper and LaunchDaemon.
2. Produce Developer ID and notarization evidence, then independently verify the
   signature, stapled ticket, and Gatekeeper distribution assessment.
3. Define a release and version policy; publish a versioned DMG and GitHub
   Release with source revision, architecture, minimum macOS version, SHA-256,
   signing status, notarization status, and release notes.
4. Complete clean-account and installed-app acceptance for first launch,
   onboarding, System Proxy apply/restore, launch at login, quit and abnormal
   recovery, sleep/network changes, upgrade, relocation, uninstall/data
   retention, and the stated downgrade or rollback policy.
5. Confirm Highcharts distribution rights and GPL compatibility, or replace it
   with a dependency whose terms match the intended distribution.
6. Reconcile the `remixicon@4.9.1` npm metadata and tagged-source license, or
   remove the remote icon dependency.
7. Generate and review complete production license/notice inventories for the
   Web bundle, Rust application, pinned Mihomo binary, and Mobile Core, including
   all required license texts and SBOM fields.
8. Decide how installed applications expose source, license, warranty, privacy,
   and third-party notices.
9. Decide release territories, release channel, manual update and rollback,
   support/contact and privacy policies, vulnerability-response ownership and
   private reporting channel, supply-chain evidence, and whether remote service
   icons remain enabled by default.
10. Obtain qualified legal review for distribution obligations and any
    jurisdiction- or store-specific statements. Do not infer approval from this
    engineering audit.
